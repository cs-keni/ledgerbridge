## The Milestone Rule

The day Phase 4 ships (risk engine complete, Testcontainers tests passing — including one integration test per Swagger fraud scenario: Normal deposit asserts score < 0.4 and no alert (negative control); Velocity spike, Large amount, Fan-out, Round-trip each assert score ≥ 0.4 and correct severity — interactive Swagger fraud scenarios working, README risk engine section updated):

**Submit applications to Wells Fargo, Capital One, Citi, and JPMorgan.** Do not wait for Phase 8.

Continue building phases 5-8 while interviewing. If an offer arrives before Phase 8 is complete, that is the correct outcome.

## Quality Gate

- README must lead with the risk engine section, not the banking CRUD features
- Every phase must maintain Testcontainers coverage
- Never ship a phase with shallow tests to advance the phase count
- The live demo URL must never require a recruiter to create an account. Strategy: V8__demo_seed.sql creates demo admin user (e.g. demo@ledgerbridge.io / demo-password-123 with read-only admin role). README 'Live Demo' section shows these credentials in a code block. Recruiter visits URL, copies credentials, logs in — sees React admin dashboard with pre-loaded risk alerts.

## NOT in scope

- Microservices extraction (modular monolith is the right architecture; don't over-engineer)
- Redis for rate limiting (nice-to-have, adds infrastructure complexity without interview value)
- Mobile app frontend (React SPA is the right choice; mobile adds scope without fintech relevance)
- Multi-tenant / multi-bank support (out of scope for a portfolio project)
- Real fraud dataset integration (synthetic scenarios are sufficient and avoidable licensing complexity)
